---
title: affected 그래프 동작 방식
description: 명시적 리비전에서 워크스페이스 작업 매트릭스까지
---

저장소 상태, 설정, base, head가 같으면 계산 결과도 결정론적으로 같습니다.

1. Git으로 명시적 리비전을 비교해 변경 경로를 구합니다.
2. 설정된 include/exclude glob과 지원 워크스페이스 메타데이터로 패키지를 탐색합니다.
3. 모든 패키지 의존성 종류에서 로컬 간선을 구성합니다. 레지스트리 범위는 로컬 버전이 npm semver를 만족할 때만 간선이 됩니다.
4. 전역 의존성 glob이 일치하면 전체를, 아니면 변경 경로를 포함한 워크스페이스를 선택합니다.
5. 역방향 간선을 전이 탐색해 변경 패키지의 의존자도 포함합니다.
6. 각 그룹 작업에 ignore 규칙을 적용하고 표준·격리·샤드 매트릭스 항목을 생성합니다.

CLI는 `--base`가 필수이고 `--head` 기본값은 `HEAD`입니다. GitHub Action은 이벤트 컨텍스트를 경계에서 해석해 두 리비전을 명시적으로 전달합니다. 따라서 그래프 로직은 GitHub 밖에서도 재사용할 수 있습니다.

격리 규칙은 `isolate: true`인 항목 하나를 만듭니다. 샤드 수 `N`은 1 기반 `shard`, `totalShards: N`인 항목 N개를 만듭니다. 같은 작업은 격리와 샤드를 동시에 사용할 수 없습니다.

매트릭스 크기 설정 때문에 작업이 조용히 사라지지 않습니다. 선택한 `(워크스페이스, 작업)`마다 필요한 항목이나 샤드 항목이 생성됩니다. 소비자는 예상 이름과 샤드 수를 검증하고 생성된 잡을 모두 실행해야 합니다.
