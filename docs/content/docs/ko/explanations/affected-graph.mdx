title: 영향 그래프 작동 원리
description: nanoom이 의존성 그래프를 만들고 에지를 분류하며 영향 프로젝트를 계산하는 방식
---

이 페이지는 영향 감지 내부 동작을 설명합니다. 이해하면 전역 의존성 설정, 예상치 못한 결과 디버깅, 출력 신뢰에 도움이 됩니다.

## 파이프라인 개요

```
바뀐 파일 → 프로젝트 매핑 → 의존성 그래프 → 영향 확장 → 매트릭스
```

1. **바뀐 파일** — 병합 베이스(또는 `COMPARISON=tip`이면 팁 커밋) 기준 `git diff`.
2. **프로젝트 매핑** — 각 파일을 그 파일을 담은 워크스페이스 프로젝트 디렉터리에 할당.
3. **의존성 그래프** — 각 프로젝트의 `package.json` 의존성에서 프로젝트 간 에지 도출.
4. **영향 확장** — 직접 바뀐 프로젝트에서 시작해 역방향 에지를 따라 전이적으로 확장.
5. **매트릭스** — 영향받은 프로젝트를 작업별로 묶고, 동시성/샤드/격리 규칙 적용, JSON 출력.

## 1단계: 바뀐 파일

디프 베이스는 이벤트로 정해집니다:

| 이벤트 | 베이스 ref | 헤드 ref |
| --- | --- | --- |
| `pull_request` | `PULL_REQUEST_BASE_REF` | `PULL_REQUEST_HEAD_REF` |
| `push` | `PUSH_REF_NAME` (부모) | `PUSH_REF_NAME` |
| `merge_group` | `MERGE_GROUP_BASE_REF` | `MERGE_GROUP_HEAD_REF` |

`COMPARISON=tip`으로 병합 베이스 대신 팁 커밋과 비교하게 바꿀 수 있습니다.

## 2단계: 프로젝트 매핑

파일은 그 파일을 포함하는 **가장 안쪽** 프로젝트 디렉터리에 매핑됩니다. 어떤 프로젝트 디렉터리에도 속하지 않은 파일(예: 루트 `README.md`)은 **아무 프로젝트에도 매핑되지 않음** — 직접 영향 프로젝트를 만들진 않지만 `globalDependencies`를 트리거할 순 있습니다.

## 3단계: 의존성 그래프 구성

에지는 각 프로젝트 `package.json`의 **네 가지 의존성 종류** 전부에서 나옵니다:

- `dependencies`
- `devDependencies`
- `peerDependencies`
- `optionalDependencies`

각 지정자(specifier)마다 nanoom이 에지를 분류합니다:

| 지정자 패턴 | 내부 에지? | 근거 |
| --- | --- | --- |
| `workspace:*` | ✅ 항상 | 명시적 워크스페이스 프로토콜 |
| `workspace:^x.y.z` / `workspace:~x.y.z` | ✅ 항상 | 범위 있는 워크스페이스 프로토콜 |
| `link:../경로` | ✅ 항상 | 로컬 파일 심링크 |
| `file:../경로` | ✅ 항상 | 로컬 타르볼/디렉터리 |
| 일반 세므버 (`^1.0.0`, `~2.1.0`, `>=1 <3`, `1.0.0`, `||` 합집합) | ✅ 로컬 버전이 범위 만족 시 | 로컬 패키지로 해석됨 |
| 해석 불가 / 레지스트리 범위 | ❌ 아니오 | npm 레지스트리 가리킴 |

**로컬 버전**은 대상 프로젝트 `package.json`의 `version` 필드입니다. `0.x.y`로 시작하는 `^` 범위는 표준 세므버 규칙(패치 변경만 허용) 적용.

예시:
```json
// packages/lib-a/package.json
{ "name": "@scope/lib-a", "version": "1.2.3" }

// packages/app/package.json
{ "dependencies": { "@scope/lib-a": "^1.0.0" } }
```
`1.2.3`이 `^1.0.0`을 만족하므로 `app → lib-a` 내부 에지가 생깁니다.

## 4단계: 영향 확장

직접 바뀐 프로젝트 집합(2단계)에서 시작해 **역방향 에지**를 따라 전이적으로 걷습니다:

```
바뀜: lib-a
역방향 에지: app → lib-a
영향: { lib-a, app }
```

결과는 **결정적 발견 순서**로 정렬된 프로젝트 이름 집합입니다 (워크스페이스 발견 중 발견된 순서).

### 전역 의존성 단축 경로

`globalDependencies` 글로브와 매치하는 파일이 바뀌면(예: `pnpm-lock.yaml`), 확장이 단축돼 **모든 프로젝트가 영향받음**이 됩니다. 이는 잠재적으로 모든 패키지에 영향을 줄 수 있는 록파일 변경을 커버합니다.

## 5단계: 매트릭스 생성

영향받은 프로젝트를 작업 그룹별로 묶습니다:

```
group "ci" (tasks: lint, test, build)
영향: { lib-a, app }
→ 매트릭스 항목:
  { name: "lib-a", path: "packages/lib-a", task: "lint" }
  { name: "lib-a", path: "packages/lib-a", task: "test" }
  { name: "lib-a", path: "packages/lib-a", task: "build" }
  { name: "app", path: "apps/app", task: "lint" }
  ...
```

### 규칙이 항목 수정

| 규칙 | 매트릭스 효과 |
| --- | --- |
| `ignore: true` | 이 프로젝트의 모든 항목을 그룹에서 제거 |
| `isolate: ["test"]` | 나열된 작업 각각이 전용 매트릭스 항목이 됨 (배칭 안 함) |
| `shard: [{ task: "test", shard: 4 }]` | 그 작업을 `shard: 1..4` 가진 4개 항목으로 분할 |

### 동시성 상한

`concurrency`는 매트릭스 잡을 동시에 몇 개까지 병렬 실행할 수 있는지에 대한 힌트입니다. 생성되는 항목은 절대 변경되지 않습니다. 모든 `(프로젝트, 작업)` 쌍은 항상 자체 매트릭스 항목을 가지므로, 작업이 조용히 삭제되거나 병합되는 일은 없습니다.

## 요약 다이어그램

```
push/PR
   │
   ▼
git diff (병합 베이스) ──► 바뀐 파일
   │                           │
   │                           ▼
   │                    프로젝트에 매핑 (디렉터리 포함)
   │                           │
   ▼                           ▼
┌─────────────────────────────────────────┐
│           워크스페이스 발견              │
│  (pnpm-workspace.yaml, turbo.json,      │
│   nx.json, package.json workspaces)     │
│                                         │
│  각 프로젝트마다:                       │
│   package.json 읽기                     │
│   네 가지 dep 종류 파싱                 │
│   각 지정자 분류                        │
│   방향 그래프 구성 (의존 → 피의존)       │
└─────────────────────────────────────────┘
   │
   ▼
바뀐 프로젝트에서 역방향 걷기
   │
   ▼
globalDependencies 맞음? ──► 예 ──► 전체 프로젝트
   │
   아니오
   │
   ▼
결정적 영향 프로젝트 집합
   │
   ▼
그룹 규칙 적용 (ignore/isolate/shard)
   │
   ▼
{ "include": [...] } 매트릭스 출력 (프로젝트/작업 쌍당 하나의 항목)
```

## 설정이 그래프에 미치는 영향

| 설정 | 그래프 영향 |
| --- | --- |
| `workspace.include` / `exclude` | 어떤 디렉터리가 프로젝트가 될지 필터링 |
| `globalDependencies` | 확장을 "전체"로 단축 |
| `group.rules.ignore` | 매트릭스에서 프로젝트 제거 (그래프에선 유지) |
| `group.rules.isolate` / `shard` | 매트릭스 항목 모양만 변경, 그래프엔 영향 없음 |

## 디버깅 팁

로컬에서 JSON 출력으로 돌려보세요:

```bash
PULL_REQUEST_BASE_REF=main PULL_REQUEST_HEAD_REF=HEAD \
  nanoom affected --json
```

출력에 전체 그래프(프로젝트, 에지, 영향 집합)가 들어있어 검사하기 좋습니다.
