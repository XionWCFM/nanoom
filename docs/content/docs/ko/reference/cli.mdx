전역 옵션은 `--config/-c`, `--cwd/-C`, 반복 가능한 `--verbose/-v`입니다. 기계 판독 명령은 JSON을 stdout에, 진단을 stderr에 유지합니다.

## `affected`

```bash
nanoom affected --base <브랜치|태그|커밋> [--head HEAD] [--matrix]
```

CLI는 `--base`가 필수이며 `--head` 기본값은 `HEAD`입니다. `--matrix`는 모든 그룹 매트릭스를 JSON으로 출력합니다. 그 외에는 `--format text|json` 또는 `--json`을 사용합니다. 기본 비교는 merge base를 사용하며 직접 base tip 비교는 `COMPARISON=tip`으로 선택합니다. GitHub 이벤트 컨텍스트는 플랫폼 독립 CLI 내부에서 추론하지 않고 복합 Action 경계에서 해석합니다.

## `run`

```bash
nanoom run <group> <task> [--all] [--filter <workspace>]
  [--runner auto|pnpm|yarn|npm|turbo|nx]
  [--shard N --total-shards N] [--isolate] [--continue-on-error]
```

샤드 플래그는 함께 제공해야 하며 `1 <= shard <= total-shards`를 만족해야 합니다. 샤드 실행은 `NANOOM_SHARD_INDEX`, `NANOOM_SHARD_TOTAL`을 내보냅니다. `--continue-on-error`는 나머지 프로젝트를 실행하지만 하나라도 실패하면 최종 종료 코드는 비정상입니다.

## `install`

```bash
nanoom install [--package-manager auto|pnpm|yarn|npm]
  [--filter <workspace>] [--workspace-install]
```

루트 install은 항상 실행합니다. `--filter`는 Yarn Berry 또는 pnpm으로 선택 워크스페이스의 의존성 폐쇄를 설치하며 npm 집중 설치는 거부됩니다. `--workspace-install`은 레거시 워크스페이스별 install도 추가 실행합니다.

## `status`

```bash
nanoom status <job,...> [--results job=status,...] [--format text|json|markdown]
```

`--results`가 없으면 `GITHUB_OUTPUT`에서 정확한 `<job>_result=<status>` 항목을 읽습니다. 상태는 `success`, `failure`, `cancelled`, `skipped`입니다. 누락되거나 알 수 없는 값은 오류이며, 실패 또는 취소는 요청한 요약을 출력한 뒤 비정상 종료합니다. JSON 모드는 stdout에 JSON 문서 하나만 출력합니다.

## 기타 명령

```bash
nanoom cache-key --runner <runner> --task <task> [--filter <workspace>] [--json]
nanoom schema [--output <file>]
nanoom version [--json]
```

`cache-key`는 지원 lockfile, 설정, runner/task/filter, 존재하는 관련 파일을 결정론적으로 해시합니다. `schema`는 현재 JSON Schema를, `version --json`은 `{name, version}`을 출력합니다. 플래그의 실행 가능한 기준은 `nanoom <command> --help`입니다.
