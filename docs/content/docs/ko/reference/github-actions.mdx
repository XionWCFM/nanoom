nanoom은 이 저장소에 다섯 개 복합 액션을 포함합니다. nanoom 저장소 안에선 로컬 경로로(`./.github/actions/...`), 포크를 게시했다면 `owner/repo/.github/actions/nanoom-affected@tag`로 쓰세요.

---

## `nanoom-affected`

영향 감지를 돌리고 잡 매트릭스를 내보냅니다.

### 사용법

```yaml
- id: detect
  uses: ./.github/actions/nanoom-affected
  with:
    group: ci # 선택: 한 그룹 매트릭스만 내보냄
```

### 입력

| 입력 | 타입 | 필수 | 기본값 | 설명 |
| --- | --- | --- | --- | --- |
| `group` | string | 아니오 | — | 단일 그룹 매트릭스만 내보냄 (예: `ci`) |
| `version` | string | 아니오 | `latest` | 설치할 nanoom 버전 (`latest` 또는 `v0.1.0`) |

### 출력

| 출력 | 타입 | 설명 |
| --- | --- | --- |
| `has-change` | string | 영향 프로젝트 1개 이상이면 `"true"` |
| `matrix` | JSON | `{ "include": [...] }` — `strategy.matrix` 바로 사용 |

### 내부 동작

1. nanoom 바이너리 설치 (버전별 캐시).
2. 이벤트 환경 변수 읽으며 `nanoom affected --json` (또는 `--matrix <group>`) 실행.
3. JSON을 `concurrency` 상한 적용해 매트릭스로 변환.
4. `has-change`와 `matrix` 출력 설정.

## `nanoom-run`

현재 러너에서 `(프로젝트, 작업)` 쌍 하나를 실행합니다.

### 사용법

```yaml
- uses: ./.github/actions/nanoom-run
  with:
    group: ci
    task: ${{ matrix.task }}
    filter: ${{ matrix.name }}
    shard: ${{ matrix.shard }}
```

### 입력

| 입력 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `group` | string | **예** | 설정의 그룹 이름 |
| `task` | string | **예** | 그룹의 `tasks`에 있는 작업 이름 |
| `filter` | string | **예** | 실행할 프로젝트 이름 (`matrix.name`에서) |
| `shard` | string | 아니오 | 샤드 인덱스 (`matrix.shard`에서) |
| `version` | string | 아니오 | `latest` — 설치할 nanoom 버전 |

### 내부 동작

1. nanoom 설치.
2. `nanoom run <그룹> <작업> --filter <필터> [--shard <샤드>]` 실행.
3. 상태 게이트용 `<잡>_result=success|failure`를 `$GITHUB_OUTPUT`에 기록.

## `nanoom-install`

발견된 모든 프로젝트(선택적으로 루트)의 의존성을 설치합니다.

### 사용법

```yaml
- uses: ./.github/actions/nanoom-install
  with:
    package-manager: auto # auto | pnpm | yarn | npm
    root-install: 'true'
```

### 입력

| 입력 | 타입 | 필수 | 기본값 | 설명 |
| --- | --- | --- | --- | --- |
| `package-manager` | string | 아니오 | `auto` | `auto`, `pnpm`, `yarn`, `npm` 중 하나 |
| `root-install` | boolean | 아니오 | `false` | 저장소 루트에도 install 실행 |
| `version` | string | 아니오 | `latest` | 설치할 nanoom 버전 |

### 감지 (auto일 때)

1. `pnpm-lock.yaml` → pnpm
2. `yarn.lock` → yarn
3. 그 외 → npm

## `nanoom-status`

잡 결과를 모아 실패가 있으면 실패시킵니다.

### 사용법

```yaml
- uses: ./.github/actions/nanoom-status
  with:
    jobs: test
    format: markdown
```

### 입력

| 입력 | 타입 | 필수 | 기본값 | 설명 |
| --- | --- | --- | --- | --- |
| `jobs` | string | **예** | — | 콤마로 구분한 잡 이름들 (예: `test` 또는 `build,test,e2e`) |
| `format` | string | 아니오 | `text` | `text`, `json`, `markdown` 중 하나 |
| `version` | string | 아니오 | `latest` | 설치할 nanoom 버전 |

### 하는 일

1. nanoom 설치.
2. 나열된 각 잡의 `$GITHUB_OUTPUT` 읽기: `<잡>_result=success|failure|cancelled|skipped`.
3. 선택한 포맷으로 요약 표 출력.
4. **어떤 잡이든 `failure`를 보고하면 1로 종료** — 필수 상태 체크로 쓰세요.

### 출력 포맷

**텍스트:**
```
test → success
test → success
test → failure
```

**마크다운:**
```markdown
| Job | Result |
|-----|--------|
| test | ✅ success |
| test | ❌ failure |
```

**JSON:**
```json
{ "results": [ { "job": "test", "result": "failure" } ] }
```

## `setup-nanoom`

nanoom 바이너리를 다운로드해 캐시하고 `$PATH`에 추가합니다.

### 사용법

```yaml
- uses: ./.github/actions/setup-nanoom
  with:
    version: latest
```

### 입력

| 입력 | 타입 | 필수 | 기본값 | 설명 |
| --- | --- | --- | --- | --- |
| `version` | string | 아니오 | `latest` | 설치할 버전 (`latest` 또는 `v0.1.0`) |

### 용도

자체 스텝에서 raw `nanoom` 명령어를 쓰고 싶을 때:

```yaml
- uses: ./.github/actions/setup-nanoom
- run: nanoom affected --json
- run: nanoom run ci test --filter @app/web
```

## 매트릭스 항목 필드

`include` 배열의 모든 항목이 가집니다:

| 필드 | 타입 | 있는 경우 | 설명 |
| --- | --- | --- | --- |
| `name` | string | 항상 | 프로젝트 이름 |
| `path` | string | 항상 | 저장소 루트 기준 상대 경로 |
| `task` | string | 항상 | 실행할 작업 이름 |
| `shard` | integer | 샤딩 시 | 1-베이스 샤드 인덱스 |
| `isolate` | string | 격리 시 | `"true"` — 전용 러너 |

## 포크 풀 리퀘스트

`GITHUB_HEAD_REPOSITORY`가 `GITHUB_REPOSITORY`와 다를 때 포크의 헤드 저장소 기준으로 병합 베이스를 풉니다. 신뢰할 수 없는 포크용 잡엔 시크릿을 넣지 마세요; nanoom 자체는 시크릿이 필요 없습니다.
