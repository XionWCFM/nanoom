이 크레이트는 라이브러리(`nanoom`)와 CLI 바이너리로 나뉩니다. CLI의 모든 기능을 Rust에서 호출할 수 있습니다.

```toml
# Cargo.toml
[dependencies]
nanoom = "0.1"
tokio = { version = "1", features = ["full"] }
```

---

## 설정

```rust
use nanoom::Config;
use std::path::Path;

// 설정 로드 및 검증
let config = Config::load(Path::new("nanoom.config.json"), Path::new("."))?;

// 그룹 접근
let ci = config.get_group("ci")?;
println!("tasks: {:?}", ci.tasks); // ["lint", "test", "build"]
```

### `Config::load(config_path, repo_root) -> Result<Config, Error>`

JSON 파일을 파싱하고 모든 필드를 검증한 뒤 타입화된 `Config`를 반환합니다. 알 수 없는 필드, 0인 concurrency, 빈 작업 목록, 빈 규칙 이름은 실행 가능한 에러와 함께 거부됩니다.

### `Config::get_group(&self, name) -> Option<&Group>`

해당 그룹이 있으면 반환합니다.

### `Config::groups(&self) -> &HashMap<String, Group>`

모든 그룹을 반환합니다.

### `Config::global_dependencies(&self) -> &[String]`

`globalDependencies`의 글로브들을 반환합니다.

### `Config::workspace(&self) -> Option<&WorkspaceConfig>`

발견 설정 오버라이드를 반환합니다.

## 워크스페이스 발견

```rust
use nanoom::workspace::Workspace;

let ws = Workspace::discover(&config, Path::new("."))?;

// 모든 프로젝트 순회
for project in ws.all_projects() {
    println!("{} ({})", project.name, project.path.display());
}

// 역방향 에지: 이 프로젝트가 바뀌면 누가 영향받나?
let lib = ws.get_project_by_name("@lib/core").unwrap();
println!("dependents: {:?}", lib.dependents); // Vec<ProjectId>
```

### `Workspace::discover(config, repo_root) -> Result<Workspace, Error>`

워크스페이스 설정(pnpm/turbo/nx/yarn 레이아웃, include/exclude 글로브)에 따라 프로젝트를 발견합니다. 프로젝트 그래프를 담은 `Workspace`를 반환합니다.

### `Workspace::all_projects(&self) -> &[Project]`

발견 순서대로 모든 프로젝트를 반환합니다.

### `Workspace::get_project_by_name(&self, name) -> Option<&Project>`

`package.json`의 `name` 필드로 조회합니다.

### `Project` 구조체

```rust
pub struct Project {
    pub id: ProjectId,
    pub name: String,
    pub path: PathBuf,
    pub package_json_path: PathBuf,
    pub version: String,                    // package.json에서
    pub dependency_specs: Vec<String>,      // 4가지 의존성 종류 전부, 원본 지정자
    pub dependents: Vec<ProjectId>,         // 역방향 에지 (내부용)
}
```

## 영향 계산

```rust
use nanoom::workspace::{Workspace, calculate_affected};
use std::path::Path;

let changed = vec![Path::new("packages/core/src/index.ts").to_path_buf()];

let affected = calculate_affected(
    &ws,
    &changed,
    &config.global_dependencies, // 록파일 등이 매치되면 "모두"로 단락
    Path::new("."),
    true,                         // 전이적 피의존 포함
);

assert!(!affected.is_empty());
// 결정론적(발견) 순서로 프로젝트 반환
```

### `calculate_affected(ws, changed_paths, global_deps, repo_root, transitive) -> Vec<&Project>`

- `changed_paths`: 변경된 파일들의 절대/상대 경로.
- `global_deps`: `Config::global_dependencies`의 글로브. 하나라도 매치되면 모든 프로젝트 반환.
- `transitive`: `true` = 역방향 에지를 전이적으로 순회 (CI 기본값); `false` = 직접 변경된 프로젝트만.

결정론적 발견 순서의 `Vec<&Project>`를 반환합니다.

## 매트릭스 생성

```rust
use nanoom::affected::{calculate, generate_matrix_for_group};

let result = calculate(&config, std::path::Path::new(".")).await?;
if result.has_change {
    let matrix = generate_matrix_for_group(&result, "ci");
    println!("{}", serde_json::to_string(&matrix)?); // {"include":[...]}
}
```

### `calculate(config, repo_root) -> Result<AffectedResult, Error>`

전체 감지 파이프라인을 실행합니다 (이벤트 환경 변수 읽기, 얕은 클론 심화, 포크 해결). `AffectedResult`를 반환합니다:

```rust
pub struct AffectedResult {
    pub has_change: bool,
    pub groups: HashMap<String, GroupMatrix>,
}
```

### `generate_matrix_for_group(result, group_name) -> Matrix`

한 그룹의 영향받은 프로젝트들을 GitHub Actions 매트릭스로 변환합니다. 규칙(ignore/isolate/shard)과 concurrency 상한을 적용합니다.

```rust
pub struct Matrix {
    pub include: Vec<MatrixEntry>,
}

pub struct MatrixEntry {
    pub name: String,
    pub path: String,
    pub task: String,
    pub shard: Option<usize>,
    pub isolate: bool,
}
```

## 작업 실행 순서

```rust
use nanoom::workspace::topological_sort;

let ordered = topological_sort(ws.all_projects());
// 의존성이 피의존보다 항상 앞에 옴
```

### `topological_sort(projects) -> Vec<&Project>`

내부 에지 위에서의 칸(Kahn) 알고리즘. 순환이 있으면 남은 프로젝트들을 뒤에 붙여서 아무 것도 묵묵히 버리지 않습니다. 이 함수로 의존성 순서대로 작업을 실행하세요.

## 에러 처리

모든 fallible API는 `Result<T, nanoom::Error>`를 반환합니다. `thiserror` 열거형으로 다음을 다룹니다:

- 설정 검증 에러 (알 수 없는 필드, 0인 concurrency, 빈 작업 목록, 빈 규칙 이름)
- Git 실패 (얕은 클론 심화, 공통 조상 없음, 포크 해결) — 힌트 포함
- 워크스페이스 파싱 에러 (package.json 없음, 중복 이름)
- 작업 실행 종료 코드 (프로젝트 문맥과 함께 래핑)

```rust
use nanoom::Error;

match Config::load(...) {
    Ok(cfg) => { /* ... */ }
    Err(Error::ConfigValidation { path, message }) => {
        eprintln!("{} 설정 에러: {}", path.display(), message);
    }
    Err(Error::Git { source, hint }) => {
        eprintln!("Git 에러: {}. 힌트: {}", source, hint);
    }
    Err(e) => eprintln!("기타 에러: {}", e),
}
```
