---
title: 풀 리퀘스트 검사 실행
description: affected, 매트릭스, 집계 전체 워크플로
---

```yaml
name: nanoom
on: [pull_request]
permissions: { contents: read }
jobs:
  affected:
    runs-on: ubuntu-latest
    outputs:
      groups: ${{ steps.calculate.outputs.groups }}
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 100 }
      - id: calculate
        uses: XionWCFM/nanoom/.github/actions/affected@v0.2.6
  run:
    needs: affected
    if: ${{ fromJSON(needs.affected.outputs.groups).ci.hasChange }}
    strategy:
      fail-fast: false
      matrix: ${{ fromJSON(needs.affected.outputs.groups).ci.matrix }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: corepack enable
      - uses: XionWCFM/nanoom/.github/actions/install@v0.2.6
        with: { matrix: "${{ toJSON(matrix) }}" }
      - uses: XionWCFM/nanoom/.github/actions/run@v0.2.6
        with: { matrix: "${{ toJSON(matrix) }}" }
  status:
    if: always()
    needs: [affected, run]
    runs-on: ubuntu-latest
    steps:
      - uses: XionWCFM/nanoom/.github/actions/status@v0.2.6
        with:
          needs: ${{ toJSON(needs) }}
          matrixJob: run
          group: ci
```

비교 베이스가 checkout 히스토리에 포함되도록 충분한 `fetch-depth`를 사용하세요. 브랜치 보호의 안정적인 필수 체크는 동적 매트릭스 잡이 아니라 `status`입니다. 릴리스 검증에서는 생성된 `run` 잡이 실제 실행됐는지도 확인해야 합니다.
