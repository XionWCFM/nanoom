description: pull_request 이벤트에서 영향 프로젝트를 감지해 잡 매트릭스로 변환하기
---

이 가이드에서는 `nanoom affected`를 `pull_request` 워크플로에 연결해, 영향받는 프로젝트만 잡을 생성하게 합니다. 이것이 nanoom 핵심 루프고, 다른 가이드들이 이 위에 쌓입니다.

## 사전 준비

- 최소 한 개 이상의 그룹이 있는 작동하는 설정 ([퀵스타트](/ko/docs/quickstart) 1단계 참고)
- 워크플로에서 복합 액션을 쓸 수 있어야 함 — nanoom 저장소 내부(`./.github/actions/...`)든, 포크한 걸 게시해 `owner/repo/.github/actions/nanoom-affected@tag`로 쓰든 상관없음

## 1단계. 감지 잡 추가

감지 잡은 풀 리퀘스트 이벤트를 읽고 두 출력을 내보냅니다:

```yaml
jobs:
  detect:
    runs-on: ubuntu-latest
    outputs:
      has-change: ${{ steps.detect.outputs.has-change }}
      matrix: ${{ steps.detect.outputs.matrix }}
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0 # 병합 베이스 계산을 위해 전체 히스토리 필요
      - id: detect
        uses: ./.github/actions/nanoom-affected
        with:
          group: ci # 선택: 한 그룹의 매트릭스만 내보냄
```

| 출력 | 타입 | 의미 |
| --- | --- | --- |
| `has-change` | string | 영향 프로젝트가 1개 이상이면 `"true"` |
| `matrix` | JSON | `{ "include": [...] }` — `strategy.matrix`가 바로 씀 |

## 2단계. 매트릭스 소비

각 매트릭스 항목은 `(프로젝트, 작업)` 쌍 하나를 설명합니다:

```yaml
  test:
    needs: [detect]
    if: ${{ needs.detect.outputs.has-change == 'true' }}
    strategy:
      matrix: ${{ fromJson(needs.detect.outputs.matrix) }}
      fail-fast: false
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ./.github/actions/nanoom-run
        with:
          group: ci
          task: ${{ matrix.task }}
          filter: ${{ matrix.name }}
          shard: ${{ matrix.shard }}
```

항목 필드:

| 필드 | 있는 경우 | 의미 |
| --- | --- | --- |
| `name`, `path`, `task` | 항상 | 프로젝트 식별자와 실행할 스크립트 |
| `shard` | 샤딩 설정됨 | 1-베이스 샤드 인덱스 |
| `isolate` | 규칙이 요구 | `"true"` — 이 항목에 전용 러너 할당 |

## 3단계. 확인

파일 하나를 건드리는 풀 리퀘스트를 올리고, Actions UI의 "Run jobs" 목록을 보세요. `test` 잡이 영향받은 프로젝트 수만큼만 팬아웃되어야 합니다. README만 고친 커밋을 푸시하면 `if:` 조건 덕분에 `test` 잡 자체가 건너뜁니다.

## 문제 해결

**파일이 바뀌었는데 매트릭스가 비어 있음.** 바뀐 파일이 모든 발견된 프로젝트 디렉터리 밖에 있거나, `ignore` 규칙이 프로젝트를 뺐을 수 있습니다. 같은 ref 쌍으로 로컬에서 `nanoom affected --json`을 돌려 감지 결과를 보세요.

**잘못된 디프 베이스.** `pull_request` 이벤트에선 nanoom이 `PULL_REQUEST_BASE_REF` / `PULL_REQUEST_HEAD_REF`를 쓰는데, Actions가 자동으로 설정합니다. 로컬 테스트에선 직접 설정하세요 — [CLI 레퍼런스: nanoom affected](/ko/docs/reference/cli#nanoom-affected) 참고.
