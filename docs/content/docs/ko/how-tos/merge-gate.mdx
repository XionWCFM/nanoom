---
title: status로 병합 차단
description: affected와 매트릭스 결과 일관성을 필수 검사로 사용
---

`status` Action은 워크플로의 `needs` 객체를 직접 판정합니다. artifact, `GITHUB_OUTPUT` 결과 줄, CLI를 사용하지 않습니다.

```yaml
status:
  if: always()
  needs: [affected, run]
  runs-on: ubuntu-latest
  steps:
    - uses: XionWCFM/nanoom/.github/actions/status@v0.2.3
      with:
        needs: ${{ toJSON(needs) }}
        affectedJob: affected
        matrixJob: run
        group: ci
        format: markdown
```

게이트가 허용하는 상태는 두 가지뿐입니다.

- `ci.hasChange=true`이고 매트릭스 잡 성공.
- `ci.hasChange=false`이고 매트릭스 잡 건너뜀.

affected 실패, 매트릭스 실패·취소, 잡 누락, 잘못된 JSON, 일관되지 않은 건너뜀은 실패합니다. 브랜치 보호에는 안정적인 `status` 잡을 필수로 지정하고 두 성공 상태와 의도적인 매트릭스 실패를 회귀 테스트하세요.
