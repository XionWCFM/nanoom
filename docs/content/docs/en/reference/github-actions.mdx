Pin public Actions to a release tag: `XionWCFM/nanoom/.github/actions/<name>@v0.2.5`. The internal setup script is loaded from that same ref; it never follows `main`.

## `affected`

```yaml
- id: affected
  uses: XionWCFM/nanoom/.github/actions/affected@v0.2.5
  with:
    cwd: .
    config: nanoom.config.json
```

| Input | Default | Description |
| --- | --- | --- |
| `version` | `latest` | Release binary tag, or `local` for repository tests |
| `cwd` | `.` | Consumer working directory |
| `config` | `nanoom.config.json` | Config path relative to `cwd` |
| `base`, `head` | event-derived | Explicit comparison revisions |

Outputs are `has_change`, `groups`, and `result`. `groups` maps each configured group to `{hasChange, matrix}`. `result` is the canonical JSON report with requested refs, resolved commit hashes, changed paths, selection reasons, and matrices. Event resolution uses standard GitHub context (`before`, `base_ref`, or merge-group base SHA) at the Action boundary and invokes the CLI with explicit revisions.

## `install`

```yaml
- uses: XionWCFM/nanoom/.github/actions/install@v0.2.5
  with:
    matrix: ${{ toJSON(matrix) }}
    packageManager: yarn
    cwd: .
```

`matrix` is required and may be one entry or an `include` wrapper. `packageManager`, `cwd`, and `version` are optional. npm is rejected because it cannot perform the required focused workspace-closure install. The `result` output records the exact command, scope, reason, CLI result, and status.

## `run`

```yaml
- uses: XionWCFM/nanoom/.github/actions/run@v0.2.5
  with:
    matrix: ${{ toJSON(matrix) }}
    packageManager: yarn
    monorepoTool: turbo
```

The required `matrix` entry supplies group, workspace, task, shard, and isolate data. Optional inputs are `packageManager`, `monorepoTool`, `cwd`, and `version`. The `result` output records the entry, exact command, reason, CLI result, and status.

## `status`

```yaml
- uses: XionWCFM/nanoom/.github/actions/status@v0.2.5
  with:
    needs: ${{ toJSON(needs) }}
    affectedJob: affected
    matrixJob: run
    group: ci
    format: markdown
```

`needs` is required. The other defaults are shown above except `format`, whose default is `text`. This Action uses `jq` directly and does not install the CLI. It succeeds only for `hasChange=true/matrix=success` or `hasChange=false/matrix=skipped`; all inconsistent, cancelled, or failed combinations fail. Its `result` output includes the observed and expected states and the decision reason.

All four Actions print their canonical result as a final JSON log group and derive notices and Step Summaries from it.

## Matrix entry

Each entry contains `group`, `name`, `path`, and `task`. Sharded entries also contain `shard` and `totalShards`; isolated entries contain `isolate: true`.

Use the final `status` job as the stable branch-protection check. A skipped matrix is valid only when `affected` explicitly reported no change.
