---
title: Configuration reference
description: nanoom.config.json fields and validation
---

Generate an editor schema with `nanoom schema --output nanoom.schema.json`. Unknown fields are rejected.

```json
{
  "$schema": "./nanoom.schema.json",
  "group": {
    "ci": {
      "tasks": ["lint", "test"],
      "rules": [
        { "name": "@repo/app", "isolate": ["test"] },
        { "name": "@repo/e2e", "shard": [{ "task": "test", "shard": 2 }] }
      ]
    }
  },
  "globalDependencies": ["yarn.lock"],
  "workspace": { "include": ["packages/*"], "exclude": [] }
}
```

| Field | Required | Contract |
| --- | --- | --- |
| `$schema` | No | Schema path or URL |
| `group` | Yes | At least one named group |
| `group.<name>.tasks` | Yes | Non-empty, unique task names |
| `group.<name>.rules` | No | Unique project-name rules |
| `rule.name` | Yes | Non-empty workspace name |
| `rule.ignore` | No | Exclude the workspace from the group |
| `rule.isolate` | No | Group tasks that require isolated entries |
| `rule.shard` | No | `{task, shard}` entries; count must be greater than zero |
| `globalDependencies` | No | Valid globs that affect all workspaces |
| `workspace.include` | No | Discovery globs; defaults to `packages/*`, `apps/*` |
| `workspace.exclude` | No | Discovery exclusion globs |

A task cannot be both isolated and sharded by the same rule. Rule task names must exist in the group's task list. Duplicate workspace package names are rejected.

Dependency edges include dependencies, devDependencies, peerDependencies, and optionalDependencies. `workspace:`, `link:`, and `file:` declarations are local edges. Registry declarations are local only when the workspace version satisfies npm-compatible semver syntax, including unions, comparators, prereleases, and hyphen ranges.

Changed workspaces expand transitively to dependents. A `globalDependencies` match affects every discovered workspace.
