Global options are `--config/-c`, `--cwd/-C`, and repeatable `--verbose/-v`. Machine-readable commands keep JSON on stdout and diagnostics on stderr.

## `affected`

```bash
nanoom affected --base <branch|tag|commit> [--head HEAD] [--json]
```

The CLI requires `--base`; `--head` defaults to `HEAD`. Text is the default. `--json` emits the one canonical `{affected, matrix}` report with requested refs, resolved full commit hashes, changed paths, and direct/transitive/global reasons. Comparisons use the merge base by default; set `COMPARISON=tip` for a direct base-tip comparison. GitHub event context is deliberately resolved by the composite Action, not inferred inside this platform-agnostic command.

## `run`

```bash
nanoom run <group> <task> [--all] [--filter <workspace>]
  [--runner auto|pnpm|yarn|npm|turbo|nx]
  [--shard N --total-shards N] [--isolate] [--continue-on-error]
```

Shard flags must be supplied together and satisfy `1 <= shard <= total-shards`. Shard execution exports `NANOOM_SHARD_INDEX` and `NANOOM_SHARD_TOTAL`. `--continue-on-error` runs the remaining projects but still exits non-zero after any failure.

## `install`

```bash
nanoom install [--package-manager auto|pnpm|yarn|npm] [--filter <workspace>]
```

The root install always runs. `--filter` installs root development tools plus the selected workspace and dependency closure with Yarn Berry or pnpm; npm focused install is rejected. JSON results include the exact command or scope and the reason for that scope.

## `status`

```bash
nanoom status <job,...> --results job=status,... [--json]
```

`--results` is required. Supported statuses are `success`, `failure`, `cancelled`, and `skipped`. Missing/unknown entries are errors; failure or cancellation prints the requested summary and exits non-zero. Use the `status` Action with `needs: ${{ toJSON(needs) }}` for cross-job GitHub aggregation. JSON mode emits exactly one JSON document on stdout.

## Other commands

```bash
nanoom cache-key --runner <runner> --task <task> [--filter <workspace>] [--json]
nanoom schema [--output <file>]
nanoom version [--json]
```

`cache-key` hashes supported lockfiles, configuration, runner/task/filter, and existing relevant files into a deterministic key. `schema` emits the current JSON Schema. `version --json` emits `{name, version}`.

Use `nanoom <command> --help` as the executable source of truth for flags.
