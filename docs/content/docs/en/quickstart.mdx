---
title: Quickstart
description: Configure and verify affected workspace execution
---

Create `nanoom.config.json`:

```json
{
  "$schema": "./nanoom.schema.json",
  "group": { "ci": { "tasks": ["lint", "test", "build"] } },
  "globalDependencies": ["yarn.lock", "tsconfig.json"]
}
```

Generate the schema and preview a real comparison:

```bash
nanoom schema --output nanoom.schema.json
nanoom affected --base main --head HEAD --matrix
nanoom run ci test --all
```

`affected` requires an explicit base in the CLI. In GitHub Actions, the public `affected` Action resolves the event revisions and passes them explicitly.

Next, copy the complete pinned workflow from [Run pull request checks](/en/docs/how-tos/pr-checks). Verify three cases: a leaf change includes its dependents, a global dependency runs every workspace, and an unrelated change produces `hasChange=false` with a skipped matrix and successful status gate.
