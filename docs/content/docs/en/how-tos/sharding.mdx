---
title: Split slow suites with sharding
description: Emit and execute distinct matrix shards
---

```json
{
  "group": {
    "ci": {
      "tasks": ["test:e2e"],
      "rules": [{
        "name": "@repo/web",
        "shard": [{ "task": "test:e2e", "shard": 4 }]
      }]
    }
  }
}
```

This emits four entries with `shard: 1..4` and `totalShards: 4`. Pass the entire entry to the Action:

```yaml
- uses: XionWCFM/nanoom/.github/actions/run@v0.2.3
  with:
    matrix: ${{ toJSON(matrix) }}
```

The task receives `NANOOM_SHARD_INDEX` and `NANOOM_SHARD_TOTAL`; wire those into the test runner's shard flags. The two CLI shard flags must appear together and form a valid one-based range.

A task cannot be both sharded and isolated in the same rule. Validation rejects that ambiguous configuration instead of silently choosing one behavior. Regression acceptance requires every expected shard job to execute and succeed, not merely a green skipped matrix.
