---
title: Run fork pull requests safely
description: Use standard event revisions without exposing secrets
---

Use the same pinned workflow as ordinary pull requests. The `affected` Action resolves `github.base_ref` and `github.sha`, fetches a missing base ref with read-only repository access, and passes explicit revisions to the CLI.

```yaml
permissions: { contents: read }
steps:
  - uses: actions/checkout@v4
    with: { fetch-depth: 100 }
  - id: affected
    uses: XionWCFM/nanoom/.github/actions/affected@v0.2.3
```

Do not use `pull_request_target` to run untrusted fork code. GitHub withholds repository secrets from ordinary fork `pull_request` workflows; keep install/run jobs usable without private tokens, or guard the secret-dependent job with `github.event.pull_request.head.repo.full_name == github.repository`.

If comparison history is unavailable, increase `fetch-depth` or fetch the base branch. Reproduce locally with `nanoom affected --base origin/main --head HEAD --matrix`; the CLI itself does not infer GitHub event environment variables.
