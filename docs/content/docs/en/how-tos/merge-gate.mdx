---
title: Gate merges with status
description: Require a consistent affected and matrix result
---

The `status` Action evaluates the workflow `needs` object directly. It does not use artifacts, `GITHUB_OUTPUT` result lines, or the CLI.

```yaml
status:
  if: always()
  needs: [affected, run]
  runs-on: ubuntu-latest
  steps:
    - uses: XionWCFM/nanoom/.github/actions/status@v0.2.6
      with:
        needs: ${{ toJSON(needs) }}
        affectedJob: affected
        matrixJob: run
        group: ci
        format: markdown
```

The gate accepts exactly two states:

- `ci.hasChange=true` and the matrix job succeeded.
- `ci.hasChange=false` and the matrix job was skipped.

An affected failure, matrix failure/cancellation, missing job, invalid JSON, or inconsistent skipped state fails. Require the stable `status` job in branch protection and exercise both accepted states plus a deliberate failing matrix in regression testing.
