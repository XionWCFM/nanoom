---
title: Run pull request checks
description: Complete affected, matrix, and aggregate workflow
---

```yaml
name: nanoom
on: [pull_request]
permissions: { contents: read }
jobs:
  affected:
    runs-on: ubuntu-latest
    outputs:
      groups: ${{ steps.calculate.outputs.groups }}
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 100 }
      - id: calculate
        uses: XionWCFM/nanoom/.github/actions/affected@v0.2.9

  run:
    needs: affected
    if: ${{ fromJSON(needs.affected.outputs.groups).ci.hasChange }}
    strategy:
      fail-fast: false
      matrix: ${{ fromJSON(needs.affected.outputs.groups).ci.matrix }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: corepack enable
      - uses: XionWCFM/nanoom/.github/actions/install@v0.2.9
        with:
          matrix: ${{ toJSON(matrix) }}
      - uses: XionWCFM/nanoom/.github/actions/run@v0.2.9
        with:
          matrix: ${{ toJSON(matrix) }}
          group: ci

  status:
    if: always()
    needs: [affected, run]
    runs-on: ubuntu-latest
    steps:
      - uses: XionWCFM/nanoom/.github/actions/status@v0.2.9
        with:
          needs: ${{ toJSON(needs) }}
          matrixJob: run
          group: ci
```

Keep `fetch-depth` large enough to contain the comparison base. The affected Action fetches a missing pull-request base branch when possible. Make `status` the stable required check; matrix job names are dynamic.

For release acceptance, confirm that the generated `run` jobs actually executed. A green `status` with `run=skipped` is valid only when `ci.hasChange` is false.
